## 이 PC의 Windows 등록

사용자의 명시적 승인으로 Windows 개발자 모드를 켰습니다. `AllowDevelopmentWithoutDevLicense` 값 하나만 설정했고 이전 값(없음)은 `work/v1.6.0/developer-mode-before.json`에 기록했습니다. 인증서를 설치하거나 로그인 정보를 변경하지 않았습니다.

현재 사용자에게 `CodexUsageMeter.WindowsWidget` 버전 `1.6.0.0`을 등록했습니다. 등록한 패키지는 같은 릴리스 소스의 로컬 빌드이며, ZIP SHA-256은 `6299b10b988b17a99eeb547984441eb65466c1dbdad79d0a8e1101cd18a1b2ec`입니다. CI의 공개 패키지는 빌드 산출물 해시가 다르므로 별도로 다운로드·검증했습니다.

- Windows 위젯 카탈로그 조회: `registered=true`, 확장 ID `CodexUsageMeterWindowsWidget` 확인.
- 운영체제의 실제 COM 서버 활성화: `HRESULT=0`.
- AUMID로 실행한 등록 제공자는 패키지 신원을 갖고, 제공자가 실행한 시험 자식은 패키지 신원이 없는 상태(15700)로 분리됨을 확인했습니다. 실패 종료 코드 감지와 카드 안내도 확인했습니다. 실제 사용자 계정/본체 실행은 사용하지 않은 격리 검사입니다.
- 320폭·200% 및 460폭·150% 글씨의 숨김 WPF 설정 화면에서 위젯 설치 버튼의 줄바꿈·경계·클릭 영역을 확인했습니다.

사용자가 Win+W 보드에 직접 고정한 화면, 실제 계정 사용량 표시, 다른 PC의 등록은 확인하지 않았습니다. 기존 실행 중 본체 v1.5.1은 해시와 프로세스를 확인해 그대로 보존했습니다. 위젯의 실제 사용량 연결은 본체 v1.6.0 업데이트 후 시작됩니다. 인증·세션·계정·이력 파일은 복사하거나 변경하지 않았습니다.

## 사용 및 보관

**미터기 ⚙ 설정 → 업데이트 확인 → 다운로드 및 재시작**으로 v1.6.0을 적용한 뒤, **Win+W → 위젯 추가 → Codex 사용량**을 고정합니다. 이 PC에는 위젯 구성요소가 이미 등록되어 있습니다. 다른 PC에서는 본체 설정의 **Windows 위젯 추가 / 업데이트**를 먼저 사용합니다. **로그인 시 시작**과 **자동 시작 시 트레이로**를 함께 켜면 로그인 때 창을 띄우지 않고 사용량을 갱신합니다.

검사 원문·종료 코드·가상 자료는 `work/v1.6.0/`, 원본 복구본은 `artifacts/v1.6.0-work/baseline/`, 최종 본체는 `bin/CodexUsageMeter.exe`에 보관합니다. 다운로드 폴더에 수동 전달본은 만들지 않았습니다. 이번 작업의 불필요한 중간 패키지·검증용 중복 출력만 최종 파일을 확인한 뒤 휴지통으로 이동하고 복구 가능성을 확인했습니다. 기존 `.mixdog/`, Git 이력·브랜치, 빌드 의존성 환경은 보존했습니다.
