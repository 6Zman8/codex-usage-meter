## 원인과 변경

첨부 화면은 텍스트 요약입니다. 조사 당시 실행 본체와 등록된 제공자는 모두 v1.6.0이고 실제 스냅샷에는 `widgetPages`가 없었습니다. 소스 v1.7.1의 공통 게이지 렌더링과 설치본 사이에 버전 차이가 있었습니다.

이미 설치한 구버전 제공자만 본체와 같은 정식 버전으로 갱신하도록 연결했습니다. 미등록·동일·상위 버전은 유지하며 다운로드 실패와 등록 결과 불일치를 성공으로 처리하지 않습니다. 개발자 모드·인증서 설정은 변경하지 않습니다.

계정은 공통 원형 게이지, PC는 CPU·GPU·RAM·디스크 세로 막대를 사용합니다. 저장 순서·항목 위치·크기·숨김을 반영하고 작은/중간/큰 위젯은 각각 최대 1/1/2장씩 표시합니다.

항목 이동·비율 크기조절에 보이는 형제 항목과 카드 안쪽의 경계·중앙선 정렬을 추가했습니다. 화면 기준 6 DIP, Alt 일시 해제, 안내선 제거를 검사했습니다. 단일 게이지의 LayoutTransform과 RenderTransform 좌표계가 달라 확대 시 어긋나던 원인도 수정했습니다.

이전 LayoutV1 좌표를 자동으로 반올림하거나 재정렬하지 않습니다. PC 기본 높이 축소가 다른 카드의 저장 배치에 영향을 주는 회귀를 재현했습니다. 기존 배치는 이전 높이를 유지하고, 새 기본 배치의 `CompactPcSpacing`만 압축된 높이를 사용하도록 수정했습니다.

- 기존 저장값의 위치·크기·순서·표시 항목·숨김을 렌더링, 편집창 열기/그대로 저장, 재실행 복원 후 비교했습니다.
- 실제 PNG의 원형 게이지·색상·세로 막대·숨김·순서를 확인했습니다. 공개 EXE에 내장된 화면도 검증한 소스와 일치합니다.

로컬 검사 자료는 `work/v1.8.0-validation-_dr3kwg_`, 공개 배포 검사 자료와 최종 EXE는 `work/release-v1.8.0-public-hvg8h0tq`에 보존했습니다. 실패 재현 자료도 남겼으며 후속 성공으로 대체하지 않았습니다.

## 실제 적용·보존·미확인 범위

실행 중인 본체의 PID·시작 시각·EXE 해시와 실제 레지스트리 LayoutV1이 검사 전후 같음을 확인했습니다. 기존 앱을 종료·교체하지 않았고 등록된 위젯도 v1.6.0 그대로입니다. 기존 계정·인증·세션을 전환하거나 복사하지 않았으며 `.mixdog/`와 기존 미추적 계획 파일을 커밋에 포함하지 않았습니다.

실제 본체 교체·재시작, 제공자 재등록, Win+W 보드에서 새 화면이 표시되는지는 이번 검사에서 실행하지 않았습니다. 자동 제공자 갱신의 분기/실패 처리는 격리 함수로 검증했으며 실제 Windows 등록 성공을 뜻하지 않습니다.

사용자는 기존 앱의 **설정 → 업데이트 확인 → 다운로드 및 재시작**으로 적용합니다. 이미 등록한 제공자의 자동 갱신이 실패하면 **Windows 위젯 추가 / 업데이트**로 재시도할 수 있습니다. 기존 카드의 높이까지 줄이려면 배치 편집에서 직접 조절하며, 업데이트가 저장 배치를 임의로 바꾸지는 않습니다.
