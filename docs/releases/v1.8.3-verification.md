## 확인한 동작

- 편집창의 버튼·제목 더블클릭과 본체 전체/위젯 모드에서 최대화 후 네 모서리를 Windows의 실제 작업영역과 비교했습니다. 복원 위치·크기와 호출 스레드의 DPI 컨텍스트도 검사했습니다.
- 로컬의 실제 4K·150% 환경에서 숨김 창의 작업영역 일치를 확인했습니다. 100/150/200%에 해당하는 작업표시줄 크기, 좌측·상단 작업표시줄, 음수·보조 화면 좌표는 4K 모의 좌표 검사입니다. 실제 Windows 배율을 변경한 검사가 아닙니다.
- 기존 배치의 위치·크기·순서·숨김 복원, 확대·스크롤·자석 정렬 검사가 통과했습니다. 배치 저장 스키마와 사용자 설정 저장 경로는 변경하지 않았습니다.
- 로컬 본체 전체 검사에서 103개 PASS, 별도 격리 계정 전환에서 13개 PASS를 확인했습니다. v1.8.3의 추가 배치·위젯 검사, 제공자 카드 28개 검사와 WinRT/COM/패키지 검사도 통과했습니다.
- GitHub 배포 검사 전체가 통과했습니다. 공개 EXE의 버전·크기·SHA-256을 확인하고 전체 검사의 103개 PASS를 확인했습니다.
- 공개 EXE의 `--windows-widget-download-test`로 같은 버전의 ZIP·해시·패키지 신원을 검증했습니다. Windows에 등록하지 않았습니다.
- 기존 v1.8.1 설치본의 `--update-check-test`가 v1.8.3을 검색하고 다운로드·해시를 검증했습니다. 실제 교체·재시작은 하지 않았습니다.

## 실패와 수정

- v1.8.2 CI https://github.com/6Zman8/codex-usage-meter/actions/runs/37920227634 는 작은 검사 화면에서 모의 4K 창이 WPF의 최대 창 크기 제한에 걸려 실패했습니다. Release는 게시되지 않았고 태그는 덮어쓰지 않았습니다.
- 별도 숨김 진단으로 WPF의 최대 창 크기 제한과 모의 제한을 지정했을 때의 차이를 확인했습니다. 실제 작업영역 검사는 그대로 두고 모의 4K 검사에만 해당 크기 제한을 지정했습니다.
- 이후 배치 보존 검사가 JSON 속성 순서 차이를 값 변경으로 오인했습니다. 저장값이나 비교 요구를 바꾸지 않고 전후 배치 복사본을 같은 방식으로 직렬화해 비교하도록 수정했습니다.
- 초기 임시 진단 도구의 `System.Xaml` 참조 누락과 임시 PowerShell 검사 스크립트의 한글 경로 인코딩 오류는 각각 참조 추가와 실행 위치에서 경로를 구하는 방식으로 수정했습니다.

## 보존 확인의 제한

- 최초 로컬 전체 검사 전후에는 기존 프로세스·설치 EXE·설정 전체 해시가 같았습니다.
- 최종 공개 파일 검사 후에도 기존 프로세스와 설치 EXE는 동일했습니다. **다만 설정 전체 해시가 최초 기준과 달라 보존 검사는 실패했습니다.** 이후 성공으로 덮어 기록하지 않습니다.
- 설정 키의 마지막 변경 시각은 `2026-10-09T10:50:50.9590578Z`로, 공개 파일 검사를 시작하기 전입니다. 최초 기준은 전체 설정의 해시만 기록했으므로 어느 값이 바뀌었는지, 사용자 조작인지까지 확정할 수 없습니다. 사용자 확인 없이 설정을 되돌리지 않았습니다.
- 실제 계정·인증·세션을 전환하거나 복사하지 않았습니다. `.mixdog/`와 기존 미추적 계획 파일을 수정·스테이징하지 않았습니다.

## 미확인

첨부 화면의 축소 최대화가 발생한 정확한 환경 조건은 재현하지 못했습니다. 기존 계산도 로컬의 일반적인 150% 조건에서는 정상 작동했습니다. 이번 변경은 좌표 변환을 제거하고 실제 창 경계로 검증한 것으로, 사용자 화면에서의 적용 확인과 구분합니다.

Windows 위젯 목록 미표시는 **미해결**입니다. 제공된 진단은 확장 등록과 런타임 준비까지만 증명합니다. 공식 manifest 문서와 C# 샘플 비교에서 목록 미표시를 설명하는 차이는 찾지 못했습니다. 실제 노트북의 위젯 보드 인식, 본체/제공자 교체와 사용자 화면에서의 최대화 결과는 확인하지 않았습니다.
