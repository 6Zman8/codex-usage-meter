# 배포 완료 기준

사용자는 미터기의 `⚙ 설정 → 업데이트 확인 → 다운로드 및 재시작`으로 정식 버전을 받습니다. 로컬 실행파일 교체만으로 배포가 완료된 것은 아닙니다.

## 배포 순서

1. `src/Program.cs`의 두 어셈블리 버전을 맞추고 `docs/releases/v버전.md`에 변경사항을 기록합니다. `docs/releases/update-summary.txt`에는 짧은 한 줄 영문 요약만 넣습니다. 1.0.6 이하의 안내창은 긴 내용으로 버튼이 잘리고 한글이 깨질 수 있으므로, 공개 Release 본문에 긴 변경사항이나 한글을 넣지 않습니다.
2. 실행 중인 미터기를 보존하도록 `build.ps1 -OutputName`에 별도의 검증용 실행파일 이름을 지정합니다.
3. 검증용 실행파일의 `--account-switch-self-test 결과파일`과 `--self-test 결과파일`을 백그라운드에서 실행하고 결과와 종료 코드를 확인합니다. 전체 검사는 Codex가 설치된 Windows 환경에서 실행합니다. 업데이트 안내 검사만 실행하려면 `--update-ui-self-test 결과파일 [미리보기폴더]`를 사용합니다. 사용자 창을 띄우지 않는 분리된 WPF 표면에서 작은 창·100~200% 글씨·버튼 클릭 영역·스크롤·연결 코드와 로컬 UTF-8 응답을 검사합니다. 실제 계정을 전환하거나 기존 앱을 종료하는 테스트는 별도 범위로 다룹니다.
4. 검토한 소스 변경을 커밋하고 원격 브랜치에 반영한 다음, 해당 커밋을 가리키는 `v버전` 태그를 게시합니다. 기존 태그와 공개 실행파일을 덮어쓰지 않습니다.
5. `.github/workflows/release.yml`의 `Build release`가 해당 태그에서 성공하고 정식 Release에 `CodexUsageMeter.exe`가 게시될 때까지 확인합니다. 자동화는 업데이트 안내 검사를 통과한 뒤 짧은 영문 요약으로 Release를 만듭니다. 같은 태그로 수동 생성을 동시에 실행하지 않습니다.
6. 공개 `releases/latest`의 버전, 짧은 영문 요약, 실행파일 크기와 SHA-256 digest를 확인하고 다운로드한 배포 파일의 버전·해시·회귀검사도 검증합니다. 상세 변경사항은 저장소의 해당 버전 문서에 보존합니다.
7. 앱의 `--update-check-test 결과파일 이전버전` 경로로 업데이트 검색 및 다운로드 검증을 확인합니다. 검증에 쓰는 해당 버전의 임시 다운로드 파일이 이미 있으면 사용자의 진행 중인 다운로드를 덮어쓰지 않습니다. 이 경로는 실제 앱 교체나 재시작을 수행하지 않습니다.
8. 배포 URL·커밋·태그·배포 파일 해시·검사 결과를 작은 기록으로 남깁니다. 검증용 중복 실행파일과 이번 작업 소유의 불필요한 중간 결과를 정리하고, 소스·최종 실행파일·기존 사용자 파일·로그인·세션은 보존합니다.
