# 계정별 사용량 이력

## 사용 방법

미터기의 **⚙ 설정 → 업데이트 확인 → 다운로드 및 재시작**으로 v1.4.0 이상을 받은 뒤 **계정 카드 → 이력**을 누릅니다. 전체·위젯 화면 모두 같은 이력 창을 엽니다.

- **잔여량 변화**: 단기·주간 잔여 비율, 예정 초기화 시각, 같은 값을 처음/마지막으로 확인한 시각.
- **초기화 전 잔여량**: 주기별 마지막 잔여 비율과 확인 시각, 예정 초기화까지 남아 있던 시간. 현재 주기도 함께 표시합니다.
- **계정/기간 선택**: 저장된 계정과 최근 7/30/90일·전체 기간. 연결 해제한 계정의 기존 기록도 남습니다.

## 기록과 관측 한계

- v1.4.0 실행 후 성공한 조회부터 기록합니다. 이전 버전에서 지난 주기의 잔여량을 소급 복원하지 않습니다.
- 기존 60초 조회를 이용합니다. 초기화 직전의 정확한 값이나 앱이 꺼져 있던 동안의 사용량을 추정하지 않습니다.
- 계정 식별자의 해시로 분리한 PC 로컬 기록을 사용합니다. 계정 칸·플랜 변경으로 다른 계정의 이력과 섞지 않습니다.
- 인증 토큰·대화·Codex DB는 이력에 저장하지 않습니다. 사용자 프로필과 기존 실행 프로그램을 보존합니다.
- 월별 기록과 직전 정상 백업을 원자적으로 저장합니다. 손상된 파일을 자동으로 덮어쓰지 않습니다.
- 기존 GitHub 정식 Release와 내장 업데이트로 전달합니다. 다운로드 폴더 전달본은 만들지 않습니다.

실제 파일은 `%LOCALAPPDATA%\CodexUsageMeter\usage-history\계정해시` 아래 `account.json`과 `YYYY-MM.json`입니다. 이메일과 플랜은 로컬 표시용이며 원래 계정 ID 대신 해시를 저장합니다. `.bak`은 직전 정상 게시본, `.pending`은 아직 게시되지 않은 저장 파일입니다. 실패 시 원본을 유지하고 `.pending` 하나만 재사용하여 중복 파일이 누적되지 않게 합니다. 월별 파일이 32 MiB를 초과하면 기록을 지우지 않고 저장 실패를 표시합니다.

조회 실패·결측·만료된 응답은 잔여량 0%나 새 주기로 바꾸지 않습니다. 예정 시각 이후 더 나중의 초기화 시각을 가진 한도를 조회해야 `초기화 후 새 한도 확인`으로 표시합니다. 값 증가·플랜 변경·한도 변경은 `잔여량·플랜·한도 변경`입니다. 주간 전용 플랜으로 바뀌어 사라진 단기 한도도 이 상태로 마감합니다. 예정 시각만 지났으면 `갱신 미확인`이며, 관측하지 못한 중간 주기는 만들지 않습니다.

한 계정의 이름 파일이 손상되어도 다른 계정 이력은 열립니다. 손상된 이름은 `이름을 읽지 못한 계정`으로 표시합니다. 선택한 월별 이력에 손상이 있으면 읽기 오류를 유지하고 원본을 덮어쓰지 않습니다. 복구가 필요한 경우 원본과 `.bak`을 모두 보존한 채 내용을 먼저 비교해야 합니다.

## 체크포인트

- 조사 완료: 기준 커밋 `99dbdb2`, 현재 정식 버전 1.3.0, 계정별 60초 RPC 조회.
- 구현 완료: 월별 저장, 계정 분리, 조회 실패/결측/플랜 전환, 이력·초기화 표와 기간 선택, 전체/위젯 진입.
- 리뷰 반영: 주간 전용 플랜의 사라진 한도 마감, 계정별 이름 파일 손상 격리, 실패 임시 파일 누적 방지, 필터 전환 중 읽기 오류 유지.
- 검증: 신규 이력 검사 16개 통과, 전체/위젯 숨김 화면·좁은 이력 창 검증. 실제 계정 전환·실제 초기화·다른 PC 실행은 시험하지 않았습니다.
- 배포 완료: 공개 실행파일·프로젝트 실행파일·실행 중인 설치본의 해시 일치, 실제 두 계정 기록 저장 및 이전 버전 내장 업데이트 검증을 확인했습니다. 상세 결과는 [v1.4.0 검증 기록](releases/v1.4.0-verification.md)에 보관합니다.
- 완료 조건: 계정 분리, 초기화 전 마지막 관측값, 관측 공백/실패 처리, 재실행 후 보존, 손상 보존, 전체·위젯 진입, 기존 회귀검사, 공개 배포 파일/내장 업데이트 검증.
